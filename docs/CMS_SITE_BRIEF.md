## Границы первой версии

- Настоящие формы и интеграции с CRM/email описываются отдельно; `formPlaceholder` ничего не отправляет.
- Не публиковать вымышленные цены, гарантии, отзывы, сертификаты и контакты.
- Не добавлять block types, пока задачу решают существующие.
- Не выполнять cloud deploy/apply без отдельного разрешения.
- Для тестовых страниц использовать `seo.noIndex: true`.

## Готовый prompt для агента без контекста

```text
Клонируй https://github.com/alexdubaev/Vibe-cms и работай в ветке main.
Это активный пользовательский репозиторий: не удаляй и не заменяй origin.
До изменений прочитай AGENTS.md, README.md, CHECKLIST.md, docs/CMS_SITE_WORKFLOW.md,
docs/CMS_SITE_BRIEF.md, docs/WEB_SURFACES.md и examples/cms-site-starter/.

Создай управляемый через CMS сайт по приложенному брифу. Бизнес-контент должен жить в CMS,
а не быть захардкожен в Astro-компонентах. Используй website для публичного HTML, webapp для
админки и backend как источник истины. Сохрани draft/preview/approval/publication flow.

Если новой page row ещё нет, добавь idempotent local-only bootstrap через существующий CMS
repository и покрой его тестом. Не используй raw SQL, не создавай production publication из
seed и не выполняй cloud deploy/apply.

Перед завершением запусти релевантные contracts/backend/webapp/website тесты, typecheck,
production website build, architecture check и git diff --check. Сообщи локальные URL,
тестовый логин, сценарий ручной проверки и production-настройки вне текущего scope.
```
