## Builder implementation

- `createSnapshotDownloader()` now parses package-bearing snapshots with the staged Site
  Package's `selectedPublicationSnapshotSchema`, extended only with the descriptor envelope.
  A positive regression test proves reverting to the old strict generic snapshot schema would
  reject the package-bearing artifact; an unknown selected-package block is rejected.
- `assertSelectedSitePackage(snapshot, descriptor)` compares ID, semantic version, and schema
  version. The exact requested mismatch is:

  ```text
  Snapshot Site Package customer-b@1.0.0 does not match builder customer-a@1.0.0
  ```

- `createAstroSiteRunner()` invokes that assertion before `mkdtemp`, `Bun.write`, or process
  spawn. A future schema version fails even when ID and package version match.
- The server explicitly wires `selectedSitePackageDescriptor`, and the builder workspace declares
  the selected-package dependency in `website-builder/package.json` and `bun.lock`.

## Selected-only images

All three Dockerfiles accept `ARG CMS_SITE_PACKAGE_ID=vibe-core` and execute
`bun scripts/stage-site-package.mjs ${CMS_SITE_PACKAGE_ID}` in a disposable package-selection
stage. The stage removes only the pre-existing ephemeral selected target first because Docker's
overlay filesystem cannot rename a lower-layer directory (`EXDEV`); the staging helper retains its
normal atomic behavior everywhere else.

- `website-builder/Dockerfile` installs only the website/builder workspace graph and copies
  contracts, `packages/selected-site-package`, website, builder, and dependencies to runtime.
  `site-packages/` never enters the runtime stage.
- `backend/Dockerfile` copies the selected package into build and runtime. Production dependencies
  are installed after the build stage so Bun's cache is reused serially; runtime never copies the
  package catalogue.
- `webapp/Dockerfile` builds the selected-package admin bundle, then copies only `webapp/dist` into
  an nginx Alpine runtime. No package TypeScript/Astro source exists in the final image.
- `.dockerignore` excludes local browser/audit/output artifacts and package-staging temporary
  siblings from build context.

## Docker smoke evidence

```text

```

The smoke builds builder, backend, and webapp with the build argument, imports the descriptor from
both Bun runtime filesystems, rejects any `/app/site-packages` or unrelated customer path, and
checks that the nginx document root contains no `.ts`, `.tsx`, or `.astro` files. It then starts:

- the builder with shape-valid fake local credentials and observes its expected HTTP 405 GET;
- the backend with a deliberately unreachable test-shaped database URL and fake S3 credentials,
  then observes HTTP 200 from `/health/live`.

Uniquely named containers and images are removed in `finally`; no shared service is stopped.
