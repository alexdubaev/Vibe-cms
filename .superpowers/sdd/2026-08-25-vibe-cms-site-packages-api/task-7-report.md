# Task 7 report — reference calculator Site Package

## Scope

Implemented Task 7 only under `site-packages/reference-calculator/` and
`examples/site-package-reference/`. The package adds one strict bespoke block,
`estimateCalculator`, while retaining the core block definitions. It owns its Astro layout,
renderer, styling, and browser formula. No backend, API, CMS runtime request, React component,
animation library, dependency, destination, Docker, or Task 8 surface was added or changed.

The unrelated untracked `.playwright-cli/`, `.ux-audit/`, `output/`, and `webapp/.21st/`
directories were preserved and were not staged.

## GREEN implementation

- `estimateCalculatorDataSchema` is a strict object with editable `title`, `description`,
  `unitPrice`, `minimumPrice`, `minimumArea`, and `maximumArea`. It rejects unknown properties,
  non-finite/negative price inputs, out-of-range values, and `maximumArea < minimumArea`.
- The selected package descriptor is `reference-calculator@1.0.0`, schema version 1. The package
  composes core block definitions with the calculator and exports package-aware page/publication
  schemas through the existing Site Package contract.
- All six fields use the generic descriptor editor. `selectedSitePackageAdmin.customEditors` is
  empty, so there is no package-specific admin runtime.
- `ReferenceLayout.astro` supplies a package-owned responsive shell, header, footer, focus state,
  and static visual language without media or external resources.
- `EstimateCalculator.astro` renders its title, description, rate, minimum, accessible labelled
  number input, bounds, and live `<output>` before its script. The code-owned formula is exactly
  `Math.max(minimumPrice, area * unitPrice)` and formatting is handled with `Intl.NumberFormat`.
- The browser test builds a temporary Astro route that imports the package's real `website.ts`
  registry. A Node-hosted Playwright Chromium session is used because direct
  `chromium.launch()` inside `bun:test` hangs on Windows; the product boundary remains a real
  browser. After initial page load, every network request is blocked for both interactions.
- `page-draft.json` and its README demonstrate the descriptor-driven CMS payload, static SEO copy,
  code-owned formula, no-index demo route, and idempotent bootstrap expectations.

## Staging evidence and default-stage blocker

The required default command was attempted unchanged:

```text
bun run site-package:stage -- reference-calculator
EPERM: operation not permitted, rename 'packages/selected-site-package' ->
'packages/selected-site-package.previous-<uuid>'
```

Root cause: the required atomic directory rename is locked on Windows by the already-running shared
Astro dev server, PID `63376`, at `http://127.0.0.1:59536`. Per repository policy and parent-agent
direction, that process was not stopped and the default staged `vibe-core` workspace was preserved.
No staging semantics or destination files were changed to bypass the lock.

The same staging function was then run with an explicit isolated `.scratch` output against the final
source tree. It succeeded and loaded this exact result:

```json
{
  "descriptor": { "id": "reference-calculator", "version": "1.0.0", "schemaVersion": 1 },
  "hasCalculator": true
}
```

The isolated staged files were deleted after validation; only empty ignored scratch directories may
remain because destructive directory removal is blocked by the execution policy.
